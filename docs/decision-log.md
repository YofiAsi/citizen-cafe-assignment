# Decision Log

Newest first. Every non-obvious technical or product decision gets a row: what was decided, and why.

| # | Decision | Rationale |
|---|---|---|
| 29 | `getCatalog`/`getCards` (`src/application/services/catalog.ts`) are wrapped in `unstable_cache` (1h revalidate) on top of the existing `cache()` | The URL is the source of truth for the deck selection (#26), so every dropdown change is a fresh navigation that re-runs the page server-side; React's `cache()` only dedupes within one request, so Neon was being hit on every single step, which is what made the picker feel slow/disabled. Content only changes via a manual reseed, so an hour of staleness is an acceptable trade for skipping the DB round trip on every navigation |
| 28 | `globals.css`'s `@theme` block is declared `@theme static` | Level colours are read only via a runtime `var(--color-level-<slug>)` built from a DB slug, never as a literal Tailwind class, so Tailwind's usage scan can't see them and was pruning every token it couldn't prove was referenced (only 4 of 24 level-colour variables were surviving the build) — `static` forces the whole block to always emit |
| 27 | Choosing a deck deals it in: the deck mounts already above the frame and rains down with the shuffle's ascending click ladder | The one moment between choosing and studying is where the game feel belongs; reusing the shuffle's landing means no second animation to maintain |
| 26 | Deck selection is URL state — `/?tier=freedom&level=indigo&type=3`, readable slugs and never database ids; the page loads the whole catalog with `getCatalog()` and derives all three dropdowns from it in memory | Only one selection exists and there is no per-user state, so the URL carries all of it: shareable, survives refresh and back/forward, needs no client store, and remounting on a slug change is what replays the deal-in. The taxonomy is 29 rows in one query, so narrowing a dropdown costs nothing and only the cards need fetching |
| 25 | Flashcard deck has sound: Web Audio one-shots for flip/next and a per-card pitch ladder for shuffle (descending out, ascending in); silent-fails and needs no user setting | Sound carries most of the game feel at near-zero cost; Web Audio (not `<audio>`) gives latency-free replay and the pitch control the ladder needs; as progressive enhancement it can never block study |
| 24 | Flashcards are a real stacked deck: every card is a stacked element, flip is a 3D spring, Next sends the card to the back, Shuffle drops the deck out of frame and stacks it back up. `--ease-spring` is a deliberate exception to Bible §13 "avoid bouncy motion", scoped to the deck | Studying should feel like handling cards, not paging a list; the deck is the one playful surface, so the overshoot is contained there and everything else stays editorially restrained |
| 23 | Fedra (brand serif) stands in as Frank Ruhl Libre via `next/font/google`; `"Fedra Serif"` stays first in the `--font-brand` stack | Fedra is a commercial Typotheque font with no licensed files in the repo; Frank Ruhl Libre is a Hebrew+Latin serif that preserves the editorial voice, and licensed files later slot in via `next/font/local` with no component changes |
| 22 | Assistant (self-hosted via `next/font`, hebrew+latin subsets) renders all UI text and all Hebrew vocabulary; the brand serif is reserved for editorial headlines | Assistant is a Hebrew-first typeface — the safest choice for nikud legibility on cards — and this keeps the Bible §6 voice split intact |
| 21 | Levels carry an identity `slug` ("red", "light-blue"), unique per tier — the seed's upsert key and the UI's source for display labels and colour tokens; supersedes the level part of #19 (`position` is ordering only again) | Removes the hardcoded (tier, position) → label mapping in the UI, makes deep-link URLs readable, and survives level insertion/reordering; rename risk accepted as rarer and migration-fixable |
| 20 | Runtime DB access uses a dedicated `app_readonly` Postgres role (SELECT-only, with default privileges for future tables); `neondb_owner` is used only by CLI operations over `DIRECT_URL` | Least privilege: a leaked runtime credential cannot modify or drop data; the app never writes |
| 19 | Taxonomy keyed by numbers: seed upserts Tier/Level/Type on `position` within their parent (no slug columns); the Level table stores no name — Tier and Type store names, level display labels are a UI mapping | Level names are colour names, i.e. display concerns; the taxonomy is a fixed progression, so numeric identity is stable; avoids keying anything on display names |
| 18 | Cards carry an explicit stable id in `seed/data.ts` (unique per deck); the seed upserts on (deck, id) | Keeps card identity stable across content edits and re-seeds, so the full product can attach per-user progress to cards without id churn |
| 17 | "Types only under Freedom" is descriptive, not enforced: no DB or domain constraint ties types to a tier | Current taxonomy happens to put types in Freedom; schema stays flexible if that changes |
| 16 | Level colours are not stored in the DB; the UI maps a level (tier + number) → its display label and design token (8a). Types inherit their level's colour | Colour is a presentation concern; keeps the Design Bible/tokens the single source of colour truth, no re-seed on palette changes |
| 15 | Content unit named "deck" (a level without types, or a level + type pair), replacing "leaf" | Flashcard-native term that reads well in domain code and UI; "leaf" was tree jargon |
| 14 | Verb citation form mixed by tier: present tense (m.sg.) in Foundation, infinitive from Flow up | Beginners meet the form they hear in speech; standard dictionary form once past survival vocab |
| 13 | Prisma 7 env wiring: `prisma.config.ts` `datasource.url` reads `DIRECT_URL` (CLI/migrations use the unpooled connection); runtime Prisma Client will use pooled `DATABASE_URL`; `.env` loaded via Node's built-in `process.loadEnvFile()` | Prisma 7 has no `directUrl` field and no longer auto-loads `.env`; the config file is consumed only by CLI tooling, so pointing it at `DIRECT_URL` gives migrations the direct connection with no extra dependency (`process.loadEnvFile` avoids adding `dotenv`) |
| 12 | Single environment: one Neon database for local, preview, and production; pooled connection string for the app, direct string for migrations | Keeps setup and seeding simple; content is static and read-only, so environment drift isn't a risk; Prisma migrations need an unpooled connection |
| 11 | Conventional Commits format (`type(scope): summary`, scopes mirror the directory areas) | Widely understood, greppable history, no tooling needed |
| 10 | Scoped `CLAUDE.md` rules per directory (root, `src/`, `src/app/`, `prisma/`, `seed/`) | Rules load in context exactly where they apply; root stays global-only |
| 9 | Decision log maintained in this file | Single place to trace why choices were made |
| 8 | Latest stable pinned exact for all packages, including TypeScript 7 (native compiler line) | Project convention: no floating ranges; latest stable checked online at add time |
| 7 | pnpm as package manager | First-class Vercel support, fast installs |
| 6 | Radix Primitives (unified `radix-ui` package), not Radix Themes | Styling comes from the Design Bible via Tailwind tokens; only behaviour/a11y needed from Radix |
| 5 | DDD layering (`domain` / `application` / `infrastructure`); no domain events or write-side plumbing | Runtime app is read-only; events add machinery with no current use case |
| 4 | Plans live in `docs/plans/<milestone><letter>-name.md` | Numbering matches the milestone map in the brief |
| 3 | Vocabulary generated offline with an AI assistant into `seed/data.ts`; no live LLM calls in the app | Content is static per level; avoids runtime cost, latency, and key management |
| 2 | No auth, no per-user state | Public-facing study tool; requirement from the brief |
| 1 | Stack: Next.js (App Router) + TypeScript, Tailwind, Radix, Prisma, PostgreSQL on Neon, Vercel | Set at project kickoff |
